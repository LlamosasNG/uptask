# Final integration fixes

Date: 2026-09-09. Branch: `feat/uptask-improvements`. Base: `cc8c43c`.

All ten findings in `final-fix-brief.md` are implemented. The binding design remains `docs/superpowers/specs/2026-09-01-uptask-improvements-design.md`. No merge, push, publication, or deployment was performed.

## Per-finding implementation and evidence

1. **Relationship injection and polluted references.** Project creation selects only `projectName`, `clientName`, and `description`, deriving the manager from authentication. Task creation selects only the five permitted planning/content fields. IDs, timestamps, history, status, and parent/child references are server-owned. Project task population matches the canonical task project; task note population matches the canonical note task. `server/tests/finalSecurity.test.ts` exercises both malicious create payloads and already-polluted arrays, and checks that foreign confidential content never appears in the HTTP response. It also confirms outsiders remain forbidden. The interrupted agent reported expected RED failures for injection and polluted population; the resumed run verified the complete suite GREEN.

2. **Project team HTTP contract.** The client project schema now accepts the API's string ID array. The server integration test authenticates a collaborator, obtains an actual project HTTP response, and parses it with the imported client schema, checking both team and task IDs. The task-workflow fixture now uses the same real wire shape. The interrupted agent reported the contract RED; the resumed suite verifies GREEN with a nonempty team, not just an empty-array fixture.

3. **Logout followed by login.** `LoginView` treats login and authenticated-user fetch as one mutation, explicitly fetching the auth query with `staleTime: 0` before protected navigation. `client/src/lib/sessionNavigation.test.tsx` mounts the real LoginView, AppLayout, React Router routes, and QueryClient, with an indefinitely fresh cached signed-out null. After the cache-removal fix, the test still failed because the user request never started and the router remained at login. It passed after user establishment was added. The delayed user response proves protected navigation waits for authenticated data.

4. **Protected cache isolation.** Ending a session cancels auth without reverting to old user data, sets the auth observer to settled null, then cancels/removes the entire projects namespace, which includes project lists, details, edit data, teams, and tasks. Successful login also ends any prior session before installing the new token. The integration test covers both explicit logout and direct account replacement, with old delayed protected responses completing after account B logs in. No A query survives. Original RED showed five protected caches remaining after logout; a subsequent mutation removing login's session cleanup failed the direct-account-change case, including the late A result reentering cache. Restoring cleanup passed both cases. Existing auth observer tests continue to prove settled success/null without an ongoing fetch. A new delayed-401 regression failed because A's response deleted B's token; the response interceptor now ends only the session whose authorization header matches the current credential.

5. **Retry-safe task/note/team transactions.** Every child creation attempt creates a fresh Mongoose document, using a stable server-owned ID and atomic `$addToSet` for the parent reference. Deletions and team removal use atomic `$pull`; note authorization is reread inside each transaction attempt. No transaction callback reuses an externally mutated parent/child document. `server/tests/transactionRetries.test.ts` has 11 integration tests using a real Mongo replica set and the driver's actual transaction abort/retry/commit machinery. The fault helper raises a labelled transient error after application writes, or an unlabelled permanent failure. Tests assert exactly one child/reference after retry, complete rollback after final failure, retained unrelated references, and atomic team access/assignment changes. A separate transient parent-write failure catches an aborted task reference leaking into a retry. The interrupted agent reported RED retry corruption for note creation, task/note deletion, and team removal; all 11 tests are GREEN in the resumed run.

6. **Atomic authentication writes and durable email ordering.** All AuthController `Promise.allSettled` compound writes are removed. Registration commits user and confirmation token together. Confirmation and password recovery reread token/user per attempt, update the user, and consume the token in one transaction. Confirmation-code requests, unconfirmed login, and password-reset requests replace prior tokens atomically. Email runs once outside the retry callback, after durable state, and its promise is awaited. `server/tests/authAtomicity.test.ts` has 19 integration tests covering both registration insert failures, user-update and token-delete failures on confirmation/reset, failed and successful token replacements on all three routes, transaction retries for confirmation/reset, and email-provider failure. Initial RED had 11 failures, including HTTP 200 after failed writes and email before persistence. Four additional RED failures established misleading provider-failure semantics, then passed after explicit durable-state errors were added.

   Provider failure deliberately returns 500 while retaining committed database state. The Spanish message explicitly says the account was created or code saved, states that email delivery failed, and directs the user to request a new code. It never suggests a rollback occurred. Failure tests verify the durable user/token remains. There is no transactional email outbox in this scope; SMTP delivery cannot be rolled back with MongoDB. Single-document profile/password operations still await and propagate their saves.

7. **Authentication error classification.** JWT parsing/verification failures, malformed subject IDs, absent credentials, and absent users return 401. Database lookup occurs outside that credential catch, so unexpected failures reach the centralized sanitized 500 handler. `finalSecurity.test.ts` injects an underlying user collection failure and asserts the complete structured 500 response; four credential variants assert 401. The interrupted agent reported the database-error RED. Build verification also found that overloaded `ReturnType<typeof jwt.verify>` resolves to the callback overload; the variable now uses the explicit synchronous payload union.

8. **Trimmed nonempty strings.** Shared express-validator chains first require a string, bail before sanitizing invalid types, trim, and then reject empty content. Both create/update routes use them for every required project/task string. Twenty table-driven cases cover whitespace and nonstring values, assert structured 422 field errors, and prove no creation or existing-name mutation happened. The interrupted agent reported expected RED for these cases; the resumed full suite verifies GREEN.

9. **Confirmed team removal and cache invalidation.** Selecting removal opens the shared ConfirmDialog with the member's name and explicit Spanish consequences for project access and task assignments. Cancel makes no DELETE; confirm performs the removal, locks the pending controls, and invalidates the project namespace so team/project data refetch and task/edit caches become stale. The real-query integration test initially failed because removal happened immediately without any dialog. GREEN checks the dialog text, cancel path, real adapter-observed deletion, refreshed empty team/project membership, and invalidated task/edit caches.

10. **Independent team permission-query states.** ProjectTeamView handles the project permission query's loading, error, retry, and 404 independently of team data. Project 403, schema, and 500 failures render inline; retry is exposed for recoverable 500 errors through the existing AsyncState policy. An actual project 404 follows the existing not-found route. Six team integration tests initially failed: three inline error variants, completed-team/pending-permission loading, independent project 404, and confirmed removal. They now all pass. The error tests keep the team request successful, so a shared mock cannot mask the missing permission branch.

## Independent re-review follow-up

The final re-review found that an optimistic status mutation from account A could fail after logout and restore A's saved project/task snapshots into account B's cleared cache. A second queued mutation could likewise resume after the account change and execute with B's credential. Both cases were reproduced RED with the real React Query mutation lifecycle. Auth sessions now carry an in-memory generation number; status mutations capture it before queuing and skip execution, rollback, notifications, and invalidation when that generation is no longer current. Both regressions pass, bringing the client suite to **64 tests in 12 files**.

The parent verification reran server tests/build/audit and client tests/lint/build/audit successfully. A fresh Chromium smoke of the rebuilt production bundle passed at 390 px and 1440 px with the expected column direction, explicit task-status changes, no document overflow, and no page errors.
